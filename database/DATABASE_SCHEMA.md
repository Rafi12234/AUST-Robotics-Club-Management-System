# AUSTRC Database Schema Contract — Neon PostgreSQL

**Database Implementation Version:** `1.1.0`  
**Platform:** Neon  
**Engine:** PostgreSQL  
**Total Tables:** 56 — 14 Shared/Core + 20 Event + 22 Administration

This file is the canonical human/AI-readable table catalog. Column definitions below use **PostgreSQL syntax**, not MySQL.

---

# 1. PostgreSQL baseline conventions

- IDs: `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- Flexible data: `JSONB`
- Application timestamps: `TIMESTAMPTZ`
- Long text: `TEXT`
- Named uniqueness: `CONSTRAINT ... UNIQUE (...)`
- Non-unique indexes: `CREATE INDEX ...`
- Automatic `updated_at`: shared PostgreSQL trigger function `set_updated_at()`
- Default UNIQUE behavior: NULLs are distinct unless explicitly changed with `NULLS NOT DISTINCT`

---

# 2. Architecture invariants

```text
evt_* -> evt_* / core_* / infra_*       allowed
adm_* -> adm_* / core_* / infra_*       allowed

evt_* -> adm_*                           forbidden
adm_* -> evt_*                           forbidden
core_* / infra_* -> evt_* / adm_*        forbidden
```

---

# 3. Core identity

`core_users` = system account/identity.  
`core_members` = official AUSTRC club member.  
`evt_participants` = event participant identity.

Do not merge or duplicate these concepts.

# 7. PostgreSQL-specific business notes

## UNIQUE + nullable columns

PostgreSQL treats NULLs as distinct in UNIQUE constraints by default. The baseline preserves that default. If a future business rule needs NULL values to collide, use `NULLS NOT DISTINCT` only through a reviewed migration.

## Email case

`core_users.email` is unique as stored. Application code should normalize account email consistently (for example lowercase before insert/update/login matching). Any future database-level case-insensitive uniqueness rule requires a migration.

## `updated_at`

The PostgreSQL baseline uses a reusable `set_updated_at()` trigger for all tables that require automatic update timestamps.

## JSONB

JSONB is used for flexible configuration/metadata. It must not replace relational tables for entities that need FKs, uniqueness, reporting, or independent history.

## TIMESTAMPTZ

TIMESTAMPTZ is used for real application timestamps. The UI/backend is responsible for presenting times in the appropriate user timezone.
