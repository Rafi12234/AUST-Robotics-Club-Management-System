# AUSTRC Central Database Documentation

**System:** AUST Robotics Club Management System  
**Database Implementation Version:** `1.1.0`  
**Logical Architecture:** unchanged from v1.0.0  
**Database Platform:** Neon  
**Database Engine:** PostgreSQL  
**Total Tables:** 56 — 14 Shared/Core + 20 Event + 22 Administration

---

## 1. Purpose

This directory is the database contract for all developers and AI coding assistants working on AUSTRC.

The database is hosted on **Neon PostgreSQL**. No MySQL syntax should be introduced into new migrations or schema code.

The documentation exists to prevent:

- Duplicate tables created by different developers or AI agents.
- Event and Administration teams modifying each other's schemas.
- Duplicate user/member/file/email/document systems.
- Manual database changes that are not represented in Git.
- PostgreSQL/MySQL syntax being mixed.
- Historical data being overwritten.
- Unreviewed changes to Shared/Core contracts.

## 4. Architecture

```text
                     NEON POSTGRESQL
                           |
                 AUSTRC CENTRAL DATABASE
                           |
          +----------------+----------------+
          |                |                |
          v                v                v
   SHARED FEATURES      EVENT          ADMINISTRATION
   core_* / infra_*     evt_*              adm_*
          ^                |                |
          +----------------+----------------+
              modules reuse Shared/Core
```

Allowed:

```text
evt_* -> core_*
evt_* -> infra_*

adm_* -> core_*
adm_* -> infra_*
```

Forbidden:

```text
evt_* -> adm_*
adm_* -> evt_*

core_* / infra_* -> evt_*
core_* / infra_* -> adm_*
```

## 7. PostgreSQL conventions used by this project

### Primary keys

Use PostgreSQL identity columns:

```sql
BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

Do not use MySQL `AUTO_INCREMENT`.

### Flexible JSON data

Use:

```sql
JSONB
```

not MySQL-oriented assumptions around `JSON`.

### Time

Use:

```sql
TIMESTAMPTZ
```

for application/business timestamps so hosted database timestamps remain timezone-safe.

### Automatic `updated_at`

PostgreSQL has no MySQL-style `ON UPDATE CURRENT_TIMESTAMP`.

The baseline schema uses the shared trigger function:

```sql
set_updated_at()
```

with per-table update triggers.

### Indexes

PostgreSQL indexes are created separately:

```sql
CREATE INDEX idx_name ON table_name (column_name);
```

### Unique constraints

Use standard PostgreSQL constraints:

```sql
CONSTRAINT constraint_name UNIQUE (column_name)
```

Remember: PostgreSQL treats `NULL` values as distinct in UNIQUE constraints by default. Use `NULLS NOT DISTINCT` only when the business rule explicitly requires nulls to collide.

## 8. Neon connection

Store the Neon connection string only in environment variables.

Example:

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

Never commit the real connection string or password.

For normal application traffic, use the Neon connection option recommended for the selected Node.js driver/ORM. A pooled Neon connection is appropriate when the application can open many concurrent connections.

## 10. Schema-change workflow

```text
Feature request
    |
    v
Search existing 56-table schema
    |
    v
Can existing schema support it?
   / \
 yes  no
  |    |
  |    v
  |  Explain schema gap
  |    |
  |  Identify table owner
  |    |
  |  Human review
  |    |
  |  PostgreSQL migration
  |    |
  v    v
Implement -> PR -> review -> merge
```

Never alter the Neon production schema manually as the normal development workflow.
